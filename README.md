# MyOS

Its just an OS that is not a linux for or something like that.

Самодельная 64-битная ОС на чистом C. Как у настоящих ОС, её
запуск - два файла:

* `BOOTX64.EFI` - маленький **загрузчик** (UEFI-программа): собирает
  у прошивки видеорежим, карту памяти, адрес ACPI, читает с того же
  диска ядро, выходит из прошивки и прыгает в ядро;
* `kernel.elf` - **ядро** по адресу `0xFFFFFFFF80000000` со своими
  таблицами страниц, своими прерываниями, таймером, памятью,
  потоками (многозадачность с вытеснением), USB/PS2-вводом,
  консолью и GUI. Прошивки под ним нет вообще.

Оба файла должны лежать рядом: `\EFI\BOOT\BOOTX64.EFI` и
`\EFI\BOOT\KERNEL.ELF` (так их раскладывают `make`, ISO и образ
диска).

## Сборка и запуск

Нужны `gcc`, `ld` (binutils), `make`; для ISO — `mtools` и `xorriso`;
для запуска — `qemu` и `edk2-ovmf`.

```bash
make            # собрать BOOTX64.EFI и kernel.elf (только изменённое)
make run        # собрать ISO и запустить в QEMU; лог ОС - прямо в терминал
make run-tablet # то же, мышь как планшет (без "упирания в стенки" в окне QEMU)
make test       # автотест в QEMU без окна (~5 минут, 15 запусков + проверка дисков)
make clean
```

Путь к прошивке по умолчанию — `/usr/share/edk2/x64/OVMF.4m.fd`
(Arch); другой: `make run OVMF=/путь/к/OVMF.fd`.

`./build.sh` и `./build_iso.sh` по-прежнему работают.

**Флешка для ноутбука:** скопировать всю папку `esp/EFI` (после
`make`) на флешку с FAT32 - то есть оба файла, не только
BOOTX64.EFI. Если загрузчик не найдёт ядро, он так и напишет.

## Отладочный лог

Весь вывод консоли ядра дублируется в последовательный порт COM1. В QEMU (`make run`, опция `-serial stdio`) он появляется в
терминале — его можно просто скопировать текстом. На ноутбуке без
COM-порта лог молча выключен.

## Рабочий стол (оконная система)

Команда `start` открывает рабочий стол в стиле Windows 95: несколько
перекрывающихся окон, перетаскивание за заголовок, кнопка закрытия,
панель задач с кнопкой «Пуск», кнопками окон, часами и индикатором
раскладки. Шрифт сглаженный, с кириллицей; курсор-стрелка.
`Ctrl+Space` переключает раскладку EN/РУ — можно печатать по-русски
(например, в Блокноте). Родные приложения: Терминал, Блокнот,
Проводник, Сапёр, О системе. Программы тоже открывают свои окна:
Часы, Рисование, Жизнь Конвея (см. `user/apps/`).

## Программы (ring 3)

С этапа 6 команды вроде `hello`, `calc`, `edit`, `guess`, `primes`,
`crash` — отдельные программы (файлы ELF), а не часть ядра. Они
работают в пользовательском режиме процессора в своей памяти и
просят ядро о чём-то системными вызовами (`sysnum.h`). Упавшая
программа завершается сама — ОС работает дальше; `Ctrl+C`
останавливает зависшую. Встроенные программы — в томе `/bin`, те же
файлы make кладёт на флешку в `\APPS\` (запуск по пути:
`/usb0p1/apps/hello`). Своя программа: файл в `user/apps/имя.c` +
`make` (мини-libc — `user/lib/`, заголовок `user/include/myos.h`).

В GUI — ярлыки на рабочем столе в стиле Windows 95: щелчок выделяет,
второй щелчок открывает; ярлыки программ запускают их в терминале.

## Файлы и диски

В корне `/` — тома: `/ram` (RAM-диск, пропадает при перезагрузке),
`/usb0p1` (первый раздел флешки), `/sata0p1`, `/nvme0p1` (разделы
внутреннего диска). Команды: `ls`, `cd`, `pwd`, `mkdir`, `rmdir`,
`touch`, `cat`, `write`, `append`, `edit`, `cp`, `mv`, `rm`, `size`,
`df`, `disk`. Понимается FAT16 и FAT32 с длинными именами.

**Писать MyOS может только на USB-флешки** (и на диски QEMU):
внутренние SATA/NVMe-диски ноутбука монтируются только для чтения —
там Arch. Проверить, что MyOS пишет правильно, можно и без Linux:
`python3 tools/fatimg.py check образ.img` (как `fsck.fat -n`).

`kpanic [null|write|stack]` — нарочно сломать само ЯДРО (экран паники); `crash` — программа, которая ломает только себя.

## Сеть и Интернет (этап 8)

Свой стек TCP/IP (`net/`): Ethernet, ARP, IPv4, ICMP, UDP, DHCP, DNS,
TCP. Адрес приходит от роутера сам (DHCP) — ничего настраивать не
нужно. Программам сеть доступна через сокеты (они же — обычные
`fd`: `read`/`write`/`close`).

| Команда | Что делает |
| --- | --- |
| `ifconfig` | интерфейсы: адрес, шлюз, DNS, MAC, счётчики |
| `ifconfig eth0 dhcp` | заново спросить адрес у DHCP |
| `ifconfig eth0 192.168.1.50/24 gw 192.168.1.1 dns 1.1.1.1` | адрес вручную |
| `ping 10.0.2.2`, `ping -c 10 example.com`, `ping -t ...` | эхо-запросы |
| `nslookup example.com` | имя → адрес |
| `wget https://archlinux.org/` | скачать по HTTP или HTTPS (в файл; `-O -` — на экран, `-O /usb0p1/x` — на флешку; `--ca-certificate файл.pem`, `--no-check-certificate`) |
| `nc хост порт` / `nc -l порт` | «голое» TCP-соединение |
| `httpd [порт] [папка]` | маленький веб-сервер: открыть `http://<адрес MyOS>/` с другого компьютера |
| `nettest` | самопроверка TCP/UDP через 127.0.0.1 |
| `net` | внутренности: ARP, соединения TCP, сокеты, кэш DNS; `net drop N` — терять каждый N-й кадр (проверка повторов TCP) |
| `wifi` | какой Wi-Fi-адаптер стоит и что с ним; `wifi selftest` — проверка WPA2; `wifi psk сеть пароль` |

Сетевые карты:

* **Intel e1000/e1000e** (82540EM, 82545EM, 82574L — проверены в QEMU;
  I217/I218/I219 — по документации);
* **Realtek RTL8111/8168, RTL8101/8106E, RTL8169** — то, что обычно
  стоит в ноутбуках (в том числе HP 250 G7), и RTL8139C+ (QEMU). Общий
  механизм колец проверен в QEMU на RTL8139C+, сами RTL8111/8106E — нет:
  в QEMU их нет;
* **USB-модем**: телефон в режиме «USB-модем» (Android: Настройки →
  Сеть → Точка доступа → USB-модем) или USB-Ethernet-переходник —
  RNDIS, CDC-ECM, CDC-NCM. Появляется интерфейс `usb0`. **Это способ
  выйти в Интернет с ноутбука без кабеля Ethernet**: телефон сам держит
  Wi-Fi или мобильную сеть.

**Wi-Fi.** Своего драйвера радиочипа пока нет: у каждого семейства
чипов своя закрытая прошивка и тысячи регистров калибровки, а проверить
такой драйвер можно только на живом чипе. Готова и проверена часть
Wi-Fi, не зависящая от чипа: ключ из пароля (PBKDF2), 4-стороннее
рукопожатие WPA2 и шифрование кадров CCMP (AES) — `wifi selftest`
(официальные тестовые векторы + рукопожатие с программной точкой
доступа). Команда `wifi` покажет, какой адаптер стоит в ноутбуке.

В QEMU сеть есть сразу (`make run`: карта e1000, адрес 10.0.2.15,
шлюз 10.0.2.2 — это сам хост, DNS 10.0.2.3). Чтобы открыть `httpd` из
браузера хоста: `make run QEMU_NET="-netdev user,id=n0,hostfwd=tcp::8080-:80 -device e1000,netdev=n0"`
и `http://localhost:8080/`.

**HTTPS.** TLS 1.2 — библиотека BearSSL (`third_party/bearssl`, MIT),
собранная для программ MyOS (`user/tls/`); сертификат сайта
проверяется по корням Mozilla (146 штук, `user/tls/roots.c`), по сроку
(нужны верные часы: CMOS в UTC, как у Arch) и по имени сайта. Случайные
числа для ключей даёт ядро (`getrandom`: RDRAND + «шум» прерываний).
Сайты, которые умеют только TLS 1.3, пока не откроются.

## Где что лежит

| Папка | Что внутри |
| --- | --- |
| `loader/` | загрузчик `BOOTX64.EFI` |
| `bootinfo.h` | "паспорт загрузки" - что загрузчик передаёт ядру, раскладка адресов |
| `myos.h` | общий заголовок: константы, типы, глобальные переменные, функции |
| `lib/` | строки, `kprintf`, COM1, `memcpy`/`memset` |
| `kernel/` | `kmain.c` (запуск ядра), `kernel.ld` (раскладка), консоль, GDT/IDT/TSS, таймер, `pmm.c` страницы, `vmm.c` таблицы страниц, `kmalloc.c` куча, `acpi.c` таблицы ACPI (ядра процессора, I/O APIC, HPET, PCIe), `power.c` часы/перезагрузка/выключение, `sched.c` потоки, планировщик, мьютексы (`ps`, `threadtest`) |
| `drivers/` | PCI, USB (xHCI, клавиатуры/мыши, хабы, флешки — с горячим подключением), PS/2 (клавиатура, мышь/тачпад), разбор HID-дескрипторов; `blk.c` диски, разделы MBR/GPT, кэш секторов; `ahci.c` SATA; `nvme.c` NVMe; сеть: `e1000.c` (Intel), `rtl8169.c` (Realtek), `usbnet.c` (USB-модемы RNDIS/ECM/NCM) |
| `net/` | стек TCP/IP: `net.c` интерфейсы и поток `net`, `arp.c`, `ip.c` (IPv4, ICMP), `udp.c`, `tcp.c`, `dhcp.c`, `dns.c`, `socket.c` сокеты, `netcmd.c` команда `net` и `ifconfig`; Wi-Fi: `wpa.c` (WPA2: SHA-1, PBKDF2, AES, CCMP, рукопожатие), `wifi.c` (адаптеры, `wifi`) |
| `user/` | программы для ring 3: `apps/` (hello, calc, edit, guess, primes, crash, сетевые ping, ifconfig, nslookup, wget, nc, httpd, nettest + оконные clock, paint, life), `lib/` мини-libc (crt0, syscall, printf, malloc, окна `win.c`, сеть `net.c`), `user.ld` |
| `sysnum.h` | номера системных вызовов — общие для ядра и программ |
| `fs/` | `vfs.c` пути, тома, открытые файлы, RAM-диск как том `/ram`; `fat.c` FAT16/FAT32 чтение и запись (длинные имена) |
| `gui/` | оконная система: `gfx.c` рисование и сглаженный шрифт, `wm.c` композитор и рабочий стол, `apps.c` родные приложения, `icons.c` значки, `minesweeper.c` логика Сапёра; `font8x16.h` (генерируется `tools/mkfont.py`) |
| `shell/` | команды шелла, ввод строки, RAM-диск, `fetch`, редактор |
| `tools/` | `autotest.py`, `split_main.py` (как был разрезан старый `main.c`) |

До этапа 0 плана вся ОС была одним файлом `main.c` на ~19 000 строк;
он лежит в первом коммите git-истории.

До этапа 1 ОС была одной UEFI-программой с командой `ebs`; эта
версия - в git-истории до коммита "Stage 1".
