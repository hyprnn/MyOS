@chapter 4. Final Preparations
@section 4.2 | Creating a Limited Directory Layout

The temporary tools built in the next chapters will be installed into the LFS partition. Create the directories they need. Brace expansion saves typing: $LFS/usr/{bin,lib,sbin} becomes three paths.

$ mkdir -pv $LFS/{etc,var} $LFS/usr/{bin,lib,sbin}

Modern distributions keep programs only in /usr/bin, /usr/lib and /usr/sbin; /bin, /lib and /sbin are symbolic links to them. Do the same in LFS:

$ ln -sv usr/bin $LFS/bin
$ ln -sv usr/lib $LFS/lib
$ ln -sv usr/sbin $LFS/sbin

The real book does this with a short for-loop; this simulated shell does not support loops, so type the three commands.

On a 64-bit (x86_64) machine some programs also expect /lib64:

$ mkdir -pv $LFS/lib64

Finally, the cross compiler of chapter 5 goes into a separate directory, so it can be thrown away later:

$ mkdir -pv $LFS/tools

$ ls -l $LFS

@section 4.3 | Adding the LFS User

Building as root is risky: one wrong command can damage the host. LFS therefore builds the temporary tools as an ordinary user called lfs. Create a group and a user:

$ groupadd lfs
$ useradd -s /bin/bash -g lfs -m -k /dev/null lfs

The options: -s sets the login shell, -g the primary group, -m creates the home directory /home/lfs and -k /dev/null keeps it empty instead of copying template files into it.

To log in as lfs with a password later, give the account one:

$ passwd lfs

## Ownership
The lfs user must be able to write into the new directories. Make it their owner. The nested braces expand to usr, all directories inside usr, and the other top-level directories:

$ chown -v lfs $LFS/{usr{,/*},lib,var,etc,bin,sbin,tools}
$ chown -v lfs $LFS/lib64

## Switching to lfs
Now start a login shell as the new user. The minus sign makes it a full login with a clean environment:

$ su - lfs

Your prompt changes and ends in $ instead of #: you are no longer root. 'exit' returns to the root shell.

! Notice that the LFS variable is empty for the lfs user. Section 4.4 fixes that.

@section 4.4 | Setting Up the Environment

The lfs user needs a small, predictable environment: compilers and build scripts react to environment variables, and anything inherited from the host can change how the packages are built. Two startup files do the job.

## First, as root: a hidden trap on the host
Many distributions ship /etc/bash.bashrc, which every interactive bash reads, also for lfs. Have a look at this host's version:

$ cat /etc/bash.bashrc

Variables like CC decide which compiler configure scripts use. Move the file out of the way (run this as root; type exit first if you are still lfs):

$ [ ! -e /etc/bash.bashrc ] || mv -v /etc/bash.bashrc /etc/bash.bashrc.NOUSE

"[ ! -e FILE ] || command" runs the command only if the file exists. When LFS is finished you can move it back.

## Then, as lfs: .bash_profile
Log in as lfs again:

$ su - lfs

A login shell reads ~/.bash_profile. Ours replaces the shell at once with a new one that starts with an EMPTY environment (env -i) except HOME, TERM and the prompt PS1:

$ cat > ~/.bash_profile << "EOF"
+ exec env -i HOME=$HOME TERM=$TERM PS1='\u:\w\$ ' /bin/bash
+ EOF

"cat > FILE << "EOF"" is a here-document: every following line is written into the file, until a line that contains only EOF. Because the word EOF is quoted, $HOME stays literally in the file instead of being replaced now. If you type it by hand, the shell shows a "> " prompt for each line. Clicking the block above pastes all of it at once.

## .bashrc
The new shell is not a login shell, so it reads ~/.bashrc:

$ cat > ~/.bashrc << "EOF"
+ set +h
+ umask 022
+ LFS=/mnt/lfs
+ LC_ALL=POSIX
+ LFS_TGT=$(uname -m)-lfs-linux-gnu
+ PATH=/usr/bin
+ if [ ! -L /bin ]; then PATH=/bin:$PATH; fi
+ PATH=$LFS/tools/bin:$PATH
+ CONFIG_SITE=$LFS/usr/share/config.site
+ export LFS LC_ALL LFS_TGT PATH CONFIG_SITE
+ EOF

What the lines mean:
- set +h turns off bash's memory of where programs are, so a newly installed tool in $LFS/tools/bin is found immediately.
- umask 022 and LFS: as in chapter 2.
- LC_ALL=POSIX keeps programs from using translated messages or unusual number formats.
- LFS_TGT is the name of the machine the cross tools build for: x86_64-lfs-linux-gnu. $(uname -m) is replaced by the output of uname -m.
- PATH starts with $LFS/tools/bin, so the cross tools win over the host's tools as soon as they are installed.
- CONFIG_SITE keeps configure scripts from reading the host's site configuration.

## Parallel builds
Modern machines have many cores. MAKEFLAGS tells every make to use all of them, which makes the builds in the next chapters several times faster (in the game too):

$ cat >> ~/.bashrc << "EOF"
+ export MAKEFLAGS=-j$(nproc)
+ EOF

Note the >>: it appends to the file instead of replacing it.

## Start the new environment
$ source ~/.bash_profile

The prompt changes to lfs:~$ and the variables are set. Check:

$ env

! The environment must show LFS, LFS_TGT, PATH starting with /mnt/lfs/tools/bin, and no CC. If CC is there, /etc/bash.bashrc was still in place: move it as root and source ~/.bash_profile again.
