@chapter 7. Entering Chroot and Building Additional Temporary Tools
@section 7.1 | Introduction

The cross-compilation is over. From now on the new system is used from the inside: chroot ("change root") starts a shell whose / is $LFS. Programs inside see only the new system: its /usr/bin, its libraries, its /etc. The host is still running underneath (the same kernel), but out of sight.

Inside, a few more tools are built that the final system needs to build itself: Gettext, Bison, Perl, Python, Texinfo and Util-linux.

From here on everything is done as root again, not as lfs.

! Inside the chroot only programs that you built exist. A command from the host such as wget or lsblk is simply "command not found" there.

@section 7.2 | Changing Ownership

Everything in $LFS is still owned by lfs. The user lfs exists only on the host: inside the chroot its number would belong to nobody, or later to some other account. Give everything to root. Leave the lfs shell first (exit) and check that you are root and that LFS is set:

$ exit
$ whoami
$ echo $LFS

--from lfs changes only what lfs owns; -R goes through whole directory trees:

$ chown --from lfs -R root:root $LFS/{usr,lib,var,etc,bin,sbin,tools}
$ chown --from lfs -R root:root $LFS/lib64

(The real book wraps the second line in a case statement for x86_64.)

@section 7.3 | Preparing Virtual Kernel File Systems

Programs talk to the kernel through some special file systems that live only in memory: /proc (processes), /sys (devices and drivers), /dev (device files), /run. Inside the chroot they must be available too. Create the mount points:

$ mkdir -pv $LFS/{dev,proc,sys,run}

## /dev
A bind mount shows an existing directory at a second place. Make the host's /dev visible as $LFS/dev:

$ mount -v --bind /dev $LFS/dev

## The others
These file systems have no device; the first word after the type is just a name for it:

$ mount -vt devpts devpts -o gid=5,mode=0620 $LFS/dev/pts
$ mount -vt proc proc $LFS/proc
$ mount -vt sysfs sysfs $LFS/sys
$ mount -vt tmpfs tmpfs $LFS/run

On some hosts /dev/shm is a symbolic link into /run; on others it needs its own tmpfs:

$ if [ -h $LFS/dev/shm ]; then
+   install -v -d -m 1777 $LFS$(realpath /dev/shm)
+ else
+   mount -vt tmpfs -o nosuid,nodev tmpfs $LFS/dev/shm
+ fi

$ mount

! These mounts disappear when the host reboots. Before entering the chroot again in a new session, mount them again (and remember to mount $LFS itself first).

@section 7.4 | Entering the Chroot Environment

Now enter. The command starts /usr/bin/env from the new system, clears the environment (-i) and starts the new system's bash as a login shell:

$ chroot "$LFS" /usr/bin/env -i   \
+     HOME=/root                  \
+     TERM="$TERM"                \
+     PS1='(lfs chroot) \u:\w\$ ' \
+     PATH=/usr/bin:/usr/sbin     \
+     MAKEFLAGS="-j$(nproc)"      \
+     TESTSUITEFLAGS="-j$(nproc)" \
+     /bin/bash --login

- PS1 marks the prompt with "(lfs chroot)", so you always know where you are.
- PATH contains only the directories of the new system. /tools is no longer used.
- $(nproc) is replaced on the host, before chroot runs.

The prompt says "I have no name!": there is no /etc/passwd inside yet, so bash cannot find a name for user number 0. That is fixed in section 7.6.

Try a few things:

$ pwd
$ ls /
$ wget --version

To leave the chroot, type exit. To come back later: mount everything from 7.3 again (as root on the host) and run the chroot command again.

@section 7.5 | Creating Directories

Create the standard directory tree of a Linux system (the Filesystem Hierarchy Standard). All of this happens inside the chroot, so / is the new system:

$ mkdir -pv /{boot,home,mnt,opt,srv}
$ mkdir -pv /etc/{opt,sysconfig}
$ mkdir -pv /lib/firmware
$ mkdir -pv /media/{floppy,cdrom}
$ mkdir -pv /usr/{,local/}{include,src}
$ mkdir -pv /usr/lib/locale
$ mkdir -pv /usr/local/{bin,lib,sbin}
$ mkdir -pv /usr/{,local/}share/{color,dict,doc,info,locale,man}
$ mkdir -pv /usr/{,local/}share/{misc,terminfo,zoneinfo}
$ mkdir -pv /usr/{,local/}share/man/man{1..8}
$ mkdir -pv /var/{cache,local,log,mail,opt,spool}
$ mkdir -pv /var/lib/{color,misc,locate}

{1..8} is a sequence: man1, man2, ... man8.

Old locations that programs still use point to /run:

$ ln -sfv /run /var/run
$ ln -sfv /run/lock /var/lock

/root is private to root; /tmp and /var/tmp are writable for everyone with the sticky bit:

$ install -dv -m 0750 /root
$ install -dv -m 1777 /tmp /var/tmp

@section 7.6 | Creating Essential Files and Symlinks

Some programs read the list of mounted file systems from /etc/mtab. The kernel provides it in /proc:

$ ln -sv /proc/self/mounts /etc/mtab

A minimal /etc/hosts. The EOF here is not quoted, so $(hostname) is replaced while the file is written:

$ cat > /etc/hosts << EOF
+ 127.0.0.1  localhost $(hostname)
+ ::1        localhost
+ EOF

## Users and groups
The user database. Only root can log in; the other accounts are for system services:

$ cat > /etc/passwd << "EOF"
+ root:x:0:0:root:/root:/bin/bash
+ bin:x:1:1:bin:/dev/null:/usr/bin/false
+ daemon:x:6:6:Daemon User:/dev/null:/usr/bin/false
+ messagebus:x:18:18:D-Bus Message Daemon User:/run/dbus:/usr/bin/false
+ uuidd:x:80:80:UUID Generation Daemon User:/dev/null:/usr/bin/false
+ nobody:x:65534:65534:Unprivileged User:/dev/null:/usr/bin/false
+ EOF

$ cat > /etc/group << "EOF"
+ root:x:0:
+ bin:x:1:daemon
+ sys:x:2:
+ kmem:x:3:
+ tape:x:4:
+ tty:x:5:
+ daemon:x:6:
+ floppy:x:7:
+ disk:x:8:
+ lp:x:9:
+ dialout:x:10:
+ audio:x:11:
+ video:x:12:
+ utmp:x:13:
+ cdrom:x:15:
+ adm:x:16:
+ messagebus:x:18:
+ input:x:24:
+ mail:x:34:
+ kvm:x:61:
+ uuidd:x:80:
+ wheel:x:97:
+ users:x:999:
+ nogroup:x:65534:
+ EOF

Some test suites in chapter 8 must run as an ordinary user. Add one called tester:

$ echo "tester:x:101:101::/home/tester:/bin/bash" >> /etc/passwd
$ echo "tester:x:101:" >> /etc/group
$ install -o tester -d /home/tester

## A new shell
bash looked up its user name when it started, when there was no /etc/passwd yet. Replace the shell with a fresh one (exec) to get rid of "I have no name!":

$ exec /usr/bin/bash --login

## Log files
Programs like login and agetty write to these files, but do not create them:

$ touch /var/log/{btmp,lastlog,faillog,wtmp}
$ chgrp -v utmp /var/log/lastlog
$ chmod -v 664  /var/log/lastlog
$ chmod -v 600  /var/log/btmp

@section 7.7 | Gettext-0.22.5

Gettext is used for translated program messages. Only three of its programs are needed now. Build time: 1.4 SBU.

$ cd /sources
$ tar -xf gettext-0.22.5.tar.xz
$ cd gettext-0.22.5

No --prefix: nothing is installed with make install. --disable-shared builds only static libraries, which is all these three programs need:

$ ./configure --disable-shared
$ make
$ cp -v gettext-tools/src/{msgfmt,msgmerge,xgettext} /usr/bin

$ cd /sources
$ rm -rf gettext-0.22.5

@section 7.9 | Perl-5.40.0

The Perl language; the build systems of many later packages are written in it. Build time: 1.0 SBU.

$ cd /sources
$ tar -xf perl-5.40.0.tar.xz
$ cd perl-5.40.0

Perl has its own configuration script, Configure (with a capital C), run with sh. -des means: accept the defaults, do not ask, and continue to the end. Every -D sets one configuration value, here mainly where the module directories go:

$ sh Configure -des                                         \
+              -D prefix=/usr                               \
+              -D vendorprefix=/usr                         \
+              -D useshrplib                                \
+              -D privlib=/usr/lib/perl5/5.40/core_perl     \
+              -D archlib=/usr/lib/perl5/5.40/core_perl     \
+              -D sitelib=/usr/lib/perl5/5.40/site_perl     \
+              -D sitearch=/usr/lib/perl5/5.40/site_perl    \
+              -D vendorlib=/usr/lib/perl5/5.40/vendor_perl \
+              -D vendorarch=/usr/lib/perl5/5.40/vendor_perl
$ make
$ make install

$ cd /sources
$ rm -rf perl-5.40.0

@section 7.12 | Util-linux-2.40.2

mount, umount, lsblk, fdisk, ... the system utilities. Build time: 0.2 SBU.

$ cd /sources
$ tar -xf util-linux-2.40.2.tar.xz
$ cd util-linux-2.40.2

The hwclock program keeps its state here:

$ mkdir -pv /var/lib/hwclock

Many programs are disabled: they need libraries that do not exist yet, or come from other packages:

$ ./configure --libdir=/usr/lib     \
+             --runstatedir=/run    \
+             --disable-chfn-chsh   \
+             --disable-login       \
+             --disable-nologin     \
+             --disable-su          \
+             --disable-setpriv     \
+             --disable-runuser     \
+             --disable-pylibmount  \
+             --disable-static      \
+             --disable-liblastlog2 \
+             --without-python      \
+             ADJTIME_PATH=/var/lib/hwclock/adjtime \
+             --docdir=/usr/share/doc/util-linux-2.40.2
$ make
$ make install

Now the chroot has a mount command of its own:

$ mount

$ cd /sources
$ rm -rf util-linux-2.40.2

@section 7.13 | Cleaning up and Saving the Temporary System

## Clean up (inside the chroot)
The documentation of the temporary tools is not needed, the libtool archives would cause trouble, and the cross-toolchain in /tools has done its job:

$ rm -rf /usr/share/{info,man,doc}/*
$ find /usr/{lib,libexec} -name \*.la -delete
$ rm -rf /tools

## Backup (optional, on the host)
The temporary system is complete and working. A backup lets you return to this point if something in chapter 8 goes badly wrong. Leave the chroot and unmount the virtual file systems first; otherwise tar would try to archive /proc and /dev:

$ exit
$ mountpoint -q $LFS/dev/shm && umount $LFS/dev/shm
$ umount $LFS/dev/pts
$ umount $LFS/{sys,proc,run,dev}

Make sure you are root and LFS is set, then:

$ cd $LFS
$ tar -cJpf $HOME/lfs-temp-tools-12.2.tar.xz .

To continue afterwards, mount the virtual file systems again (7.3) and enter the chroot (7.4).
